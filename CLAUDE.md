# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**ELEVATOR** — an Angular 19 frontend for a free, AI-powered CV/résumé builder. It is built on an **ABP (ASP.NET Boilerplate / ASP.NET Zero-style) Angular template**, so a large amount of the plumbing (auth, multi-tenancy, localization, NSwag service proxies, `abp-ng2-module`) is framework boilerplate. On top of that sits a bespoke **"ELEVATOR" design/animation layer** (`elv-*` classes, `elvReveal` directive, boot-doors intro). Most product work happens in the ELEVATOR layer; most infra questions are answered by ABP conventions.

## Commands

```bash
npm start          # ng serve on 0.0.0.0:4200 (no HMR) — normal dev
npm run hmr        # ng serve with HMR
npm test           # Karma + Jasmine (watch mode)
npm run lint       # ESLint (eslint.config.js, flat config)
npm run prettier   # format the whole repo
npm run e2e        # Protractor (legacy)
```

- **Run a single test:** there is no per-file test flag wired up; focus a spec with Jasmine `fdescribe` / `fit` (or temporarily narrow the `include` glob in `src/tsconfig.spec.json`), then `npm test`.
- **Regenerating API proxies:** `src/shared/service-proxies/service-proxies.ts` is **generated by NSwag from `swagger.json`** — do not hand-edit it. Regenerate via the `nswag` toolchain when the backend contract changes.

## Runtime configuration & mocking (read before debugging "why is it calling X")

- **`src/environments/environment.ts`** is the source of truth in dev. `angular.json` `fileReplacements` swaps it for `environment.prod.ts` (prod) or `environment.hmr.ts` (hmr build).
- **`useMocks: true`** (current default in `environment.ts`) routes all HTTP through **MSW** (`src/mocks/`, handlers in `src/mocks/handlers.ts`). When mocks are on, `API_BASE_URL` is `''` and client hydration is disabled (see `main.ts`). To hit a real backend, set `useMocks: false`.
- **Backend URL is not hardcoded.** At startup `AppInitializer` fetches `assets/appconfig.json` (selected by `environment.appConfig`) to populate `AppConsts.remoteServiceBaseUrl` / `appBaseUrl`. There are `appconfig.json`, `appconfig.container.json`, `appconfig.production.json` variants.

## Bootstrapping flow

Standalone bootstrap (`src/main.ts`), **zoneless change detection** (`provideExperimentalZonelessChangeDetection`). Boot order:

1. `enableMocking()` starts the MSW worker if `useMocks`, then calls `bootstrapApplication(RootComponent, …)`.
2. `APP_INITIALIZER` runs `AppInitializer.init()` **before** the app renders: loads `appconfig.json` → resolves tenant (subdomain / query-string resolvers) → `GET /AbpUserConfiguration/GetAll` (merged into the global `abp` object) → `AppSessionService.init()` → registers Angular locale data.
3. PrimeNG is configured with the custom **`ElevatorPreset`** theme (`src/app/theme/my-preset.ts`); dark mode selector is `.app-dark`; PrimeNG styles are placed in a `primeng` CSS layer.

Because config is fetched during `APP_INITIALIZER`, the global `abp` object (localization, auth, tenant, clock) is only fully populated after init — code that runs earlier can't rely on it.

## Routing & module structure

- Nesting: `root-routing.module.ts` → `app-routing.module.ts`. Feature areas are **lazy-loaded NgModules** that are children of `AppComponent`: `home`, `about`, `users`, `roles`, `tenants`. `account/` lives outside the app shell (login/register).
- All app routes are guarded by **`AppRouteGuard`**; permission-gated routes carry `data: { permission: 'Pages.Xxx' }`.
- Note the app is a **hybrid**: bootstrapped standalone, but still uses NgModules for feature areas. Individual components are increasingly `standalone: true` (e.g. `LandingComponent`, `AboutComponent`). Follow the pattern of the file you're editing.

## Path aliases (defined in `src/tsconfig.json`)

Always import via these, not deep relative paths:

- `@shared/*` → `src/shared/*`
- `@app/*` → `src/app/*`
- `@abp/*` → `abp-ng2-module` internals
- `@node_modules/*` → `node_modules/*`

## ELEVATOR design/animation layer

- **`elvReveal` directive** (`src/shared/directives/reveal.directive.ts`, selector `[elvReveal]`): IntersectionObserver scroll-reveal with 12 effects (`rise` default, `left`, `right`, `pop`, `flip`, `doors`, `iris`, `scan`, `wipe`, `zoom`, `glitch`, `drop`). Inputs: `[revealDelay]` (s), `[revealY]`, `[revealOnce]` (default `true`), `[revealThreshold]`. It only toggles classes via `Renderer2`, so it's safe under OnPush/zoneless. Hidden states are gated behind `prefers-reduced-motion: no-preference`.
- Reusable branded components live in `src/shared/components/` (`elv-button`, `elv-card`, `elv-chip`, `stats`, `hero-title`, `fx-grain`).
- Theming reads CSS custom properties `--p-elevator-*` (accent, glow, ink, bg, navbar-height, …) produced by the PrimeNG preset. Prefer these over hardcoded colors.
- Global visual styles: `src/styles.scss` (`@use "./reveals.scss"`, `@use "./elv-circuit.scss"`, `@import "tailwindcss"`). Tailwind v4 with custom breakpoints (`mobile: 900px`, `tablet: 1120px`, `desktop: 1024px`).

## CSS scoping gotcha (non-obvious, has caused real bugs)

Components use Angular's default **`ViewEncapsulation.Emulated`**, so rules in a `*.component.scss` are scoped to that component only. Shared-looking classes like `.elv-hero` are defined in **`landing.component.scss`** and therefore **do NOT apply** if another component (e.g. `about`) reuses the same `elv-*` markup — that page will silently lose padding/layout. Also, the header is **`position: fixed`** (out of flow), so each page must reserve its own top offset. When a hero/section renders correctly in one component but is broken (e.g. hidden under the navbar) in another that copied the HTML: the cause is almost always that the scoped SCSS wasn't copied. Fix by moving shared rules into global `styles.scss` or reusing the component, rather than patching with ad-hoc `pt-*` utilities.

## Conventions

- FontAwesome **Pro** icon CSS is loaded via CDN `<link>` tags in `app.component.html` (not npm) — Pro icon classes work at runtime but won't resolve offline.
- Prefer `OnPush` + signals/`Renderer2` patterns; the app is zoneless, so manual `markForCheck` / async pipes matter.
- Legacy files ending in `_old` (e.g. `header.component_old.html`) are dead references kept for comparison — don't wire them up.
