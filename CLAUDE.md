# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**ELEVATOR** — an Angular 19 frontend for a free, AI-powered CV/résumé builder. It is built on an **ABP (ASP.NET Boilerplate / ASP.NET Zero-style) Angular template**, so a large amount of the plumbing (auth, multi-tenancy, localization, NSwag service proxies, `abp-ng2-module`) is framework boilerplate. On top of that sits a bespoke **"ELEVATOR" design/animation layer** (`elv-*` classes, `elvReveal` directive, boot-doors intro). Most product work happens in the ELEVATOR layer; most infra questions are answered by ABP conventions.

## Commands

```bash
npm start          # ng serve on 0.0.0.0:4200 (no HMR) — normal dev
npm run hmr        # ng serve with HMR
npm test           # Karma + Jasmine (watch mode)
npm run lint       # ESLint (eslint.config.js, flat config)
npm run prettier   # format the whole repo
npm run e2e        # Protractor (legacy)
```

- **Run a single test:** there is no per-file test flag wired up; focus a spec with Jasmine `fdescribe` / `fit` (or temporarily narrow the `include` glob in `src/tsconfig.spec.json`), then `npm test`.
- **Regenerating API proxies:** `src/shared/service-proxies/service-proxies.ts` is **generated by NSwag from `swagger.json`** — do not hand-edit it. Regenerate via the `nswag` toolchain when the backend contract changes.
- **The dev server does not rebuild global CSS when you edit a partial** under `src/styles/`. Editing `styles.scss` itself does trigger it; editing `_base.scss`, `_header.scss`, etc. does not — `ng serve` keeps serving the old `styles.css`. If a SCSS change appears to have no effect, verify with `curl localhost:4200/styles.css` before debugging the cascade, then restart the server. Template edits *do* trigger a Tailwind rescan, so new utility classes appear normally.

## Runtime configuration & mocking (read before debugging "why is it calling X")

- **`src/environments/environment.ts`** is the source of truth in dev. `angular.json` `fileReplacements` swaps it for `environment.prod.ts` (prod) or `environment.hmr.ts` (hmr build).
- **`useMocks: true`** (current default in `environment.ts`) routes all HTTP through **MSW** (`src/mocks/`, handlers in `src/mocks/handlers.ts`). When mocks are on, `API_BASE_URL` is `''` and client hydration is disabled (see `main.ts`). To hit a real backend, set `useMocks: false`.
- **Backend URL is not hardcoded.** At startup `AppInitializer` fetches `assets/appconfig.json` (selected by `environment.appConfig`) to populate `AppConsts.remoteServiceBaseUrl` / `appBaseUrl`. There are `appconfig.json`, `appconfig.container.json`, `appconfig.production.json` variants.

## Bootstrapping flow

Standalone bootstrap (`src/main.ts`), **zoneless change detection** (`provideExperimentalZonelessChangeDetection`). Boot order:

1. `enableMocking()` starts the MSW worker if `useMocks`, then calls `bootstrapApplication(RootComponent, …)`.
2. `APP_INITIALIZER` runs `AppInitializer.init()` **before** the app renders: loads `appconfig.json` → resolves tenant (subdomain / query-string resolvers) → `GET /AbpUserConfiguration/GetAll` (merged into the global `abp` object) → `AppSessionService.init()` → registers Angular locale data.
3. PrimeNG is configured with the custom **`ElevatorPreset`** theme (`src/app/theme/my-preset.ts`); dark mode selector is `.app-dark`; PrimeNG styles are placed in a `primeng` CSS layer.

Because config is fetched during `APP_INITIALIZER`, the global `abp` object (localization, auth, tenant, clock) is only fully populated after init — code that runs earlier can't rely on it.

## Routing & module structure

- Nesting: `root-routing.module.ts` → `app-routing.module.ts`. Feature areas are **lazy-loaded NgModules** that are children of `AppComponent`: `home`, `about`, `users`, `roles`, `tenants`. `account/` lives outside the app shell (login/register).
- All app routes are guarded by **`AppRouteGuard`**; permission-gated routes carry `data: { permission: 'Pages.Xxx' }`.
- Note the app is a **hybrid**: bootstrapped standalone, but still uses NgModules for feature areas. Individual components are increasingly `standalone: true` (e.g. `LandingComponent`, `AboutComponent`). Follow the pattern of the file you're editing.

## Path aliases (defined in `src/tsconfig.json`)

Always import via these, not deep relative paths:

- `@shared/*` → `src/shared/*`
- `@app/*` → `src/app/*`
- `@abp/*` → `abp-ng2-module` internals
- `@node_modules/*` → `node_modules/*`

## ELEVATOR design/animation layer

- **`elvReveal` directive** (`src/shared/directives/reveal.directive.ts`, selector `[elvReveal]`): IntersectionObserver scroll-reveal with 12 effects (`rise` default, `left`, `right`, `pop`, `flip`, `doors`, `iris`, `scan`, `wipe`, `zoom`, `glitch`, `drop`). Inputs: `[revealDelay]` (s), `[revealY]`, `[revealOnce]` (default `true`), `[revealThreshold]`. It only toggles classes via `Renderer2`, so it's safe under OnPush/zoneless. Hidden states are gated behind `prefers-reduced-motion: no-preference`.
- Reusable branded components live in `src/shared/components/` (`elv-button`, `elv-card`, `elv-chip`, `stats`, `hero-title`, `fx-grain`).
- Theming reads CSS custom properties `--p-elevator-*` (accent, glow, ink, bg, navbar-height, …) produced by the PrimeNG preset. Prefer these over hardcoded colors.
- Global visual styles: `src/styles.scss` (`@import "tailwindcss"` plus a `@use` list of partials in `src/styles/` — tokens, base, page, typography, layout, animations, header, logo-fx, seam, boot, fx, hero). Tailwind v4 with custom breakpoints (`mobile: 900px`, `tablet: 1120px`, `desktop: 1024px`).
- **Navbar offset is automatic.** `src/styles/_header.scss` gives the `app-header` host `display:block; height: var(--p-elevator-navbar-height)`, so the fixed bar reserves its own space in normal flow. Pages must **not** add their own top padding — change `navbarHeight` in `my-preset.ts` and everything follows. For a full-viewport page, subtract it: `h-[calc(100dvh-var(--p-elevator-navbar-height))]`.

## Reusable effect utilities

Two global, markup-only effects. Both are pure CSS driven by custom properties — no directive, no component, no imports.

**`.elv-seam`** (`src/styles/_seam.scss`) — hairline divider with a light that runs down it. `position:absolute` + `pointer-events:none` at `z-index:2`, so it costs zero layout and can sit between two `w-1/2` panels without taking a pixel. **The parent must be `position: relative`.** Vertical only.

```html
<span class="elv-seam elv-seam--scan"
      style="--elv-seam-dur:6s; --elv-seam-runs:infinite" aria-hidden="true"></span>
```

| Property | Default | Controls |
|---|---|---|
| `--elv-seam-x` | `50%` | where the seam's **centre** lands in the parent |
| `--elv-seam-w` | `1px` | hairline thickness |
| `--elv-seam-line` | `--p-elevator-line-strong` | hairline colour (fades out over the top/bottom 12%) |
| `--elv-seam-glow` | `--p-elevator-accent` | light colour — also drives both drop-shadows |
| `--elv-seam-beam` | `3px` | width of the travelling light |
| `--elv-seam-len` | `26%` | comet length, as a share of the seam's height |
| `--elv-seam-bleed` | `28px` | element width = horizontal room before `overflow:hidden` clips the bloom |
| `--elv-seam-dur` | `2s` | one cycle. With `--scan`, visible travel is `dur ÷ 3` |
| `--elv-seam-delay` | `0s` | start delay |
| `--elv-seam-runs` | `1` | iteration count; `infinite` works |

`.elv-seam--scan` swaps in keyframes that pack the travel into the first third of the cycle and rest for the remainder — a bare `.elv-seam` fires once on mount and is easy to miss. Under `prefers-reduced-motion` the beam is hidden and the hairline stays.

**`.elv-logo-stack` / `.elv-logo-fx`** (`src/styles/_logo-fx.scss`) — a glow that crawls a logo's outline. Two mask layers composited with `intersect`: the PNG's **alpha** gives the shape, an `feTurbulence` tile's **luminance** decides where light gets through (the CSS equivalent of a Blender noise-driven emission mask).

```html
<span class="elv-logo-stack w-[min(48%,240px)]" aria-hidden="true">
  <img src="/assets/img/Logo_outline.png" alt="" />
  <span class="elv-logo-fx"></span>
</span>
```

Wrapper needs only a width; the `<img>` supplies the height. Override `--elv-logo-src` to reuse it on another mark. Tune via `baseFrequency` (Blender's Scale) and `numOctaves` (Detail) in the partial. **Never animate `baseFrequency`** — it re-runs the filter on the CPU every frame; only the noise's position animates.

## CSS scoping gotcha (non-obvious, has caused real bugs)

Components use Angular's default **`ViewEncapsulation.Emulated`**, so rules in a `*.component.scss` are scoped to that component only. Shared-looking classes like `.elv-hero` are defined in **`landing.component.scss`** and therefore **do NOT apply** if another component (e.g. `about`) reuses the same `elv-*` markup — that page will silently lose padding/layout. When a hero/section renders correctly in one component but is broken in another that copied the HTML: the cause is almost always that the scoped SCSS wasn't copied. Fix by moving shared rules into global `styles.scss` or reusing the component, rather than patching with ad-hoc `pt-*` utilities.

## Cascade layers beat specificity (the `!` you keep needing)

Tailwind v4 emits every utility inside `@layer utilities`. The hand-written SCSS in `src/styles/` and all vendor CSS (AdminLTE, AdminLTE-derived `.login-page` / `.login-box`) are **unlayered** — and unlayered styles win over layered ones *regardless of specificity or source order*. So `w-full` silently loses to `.elv-container { width: min(...) }`, and `bg-white` loses to `body { background-color: #fff }`.

Two consequences worth internalising:

- Reaching for Tailwind's `!` suffix (`w-full!`, `min-h-0!`) usually means you're fighting an unlayered class. Removing that class is almost always better than forcing the utility.
- `min-height` beats `height` — `.elv-page`'s `min-height: 100vh` will override any `h-*` utility. Kill it with `min-h-0!` or drop `.elv-page`.

Also: **`min-height`/`height` percentages need a definite ancestor chain.** `app-root` has no CSS at all, and route components declared without a `selector` render as `<ng-component>` — both unknown elements, both `display:inline`, so `h-full` beneath them collapses to `auto`. Give the component host a box (`host: { style: 'display:block; height:100dvh' }`) or use viewport units.

## Conventions

- FontAwesome **Pro** icon CSS is loaded via CDN `<link>` tags in `app.component.html` (not npm) — Pro icon classes work at runtime but won't resolve offline.
- Prefer `OnPush` + signals/`Renderer2` patterns; the app is zoneless, so manual `markForCheck` / async pipes matter.
- Legacy files ending in `_old` (e.g. `header.component_old.html`) are dead references kept for comparison — don't wire them up.
